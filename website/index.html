02 · Code

Start small.
Add the service layer when you need it.

The HTTP runtime works on its own. Discovery, peer routing and live configuration are separate imports, not mandatory ceremony.

server.ts 
import openmesh from 'openmesh-node';
import { jsonBody } from 'openmesh-node/plugins';

const app = openmesh();
app.use(jsonBody());

app.get('/users/:id', ctx => ({
  id: ctx.params.id
}));

await app.listen({ port: 3000 });
Native request path

Router → middleware → handler → response stays inside the Node.js runtime.

04 · Why OpenMesh

The difference is not another router.

OpenMesh keeps the HTTP core small, then adds the service-runtime pieces that normally become separate glue code across a Node.js system.

01

HTTP and service runtime in one model

Route requests locally, then discover and call remote peers without changing the mental model of the application.

02

Discovery is live state, not a polling loop

Expiring registrations, monotonic membership revisions and resumable SSE watches keep peer membership current.

03

Failure behavior is built into peer calls

Deadlines, safe retries, circuit state, rendezvous selection and per-peer latency telemetry travel with the mesh layer.

04

Strict TypeScript is the source of truth

One strict TypeScript tree emits ESM, CommonJS and declarations. The core keeps zero runtime dependencies.
