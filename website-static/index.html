The data path

02 peer mesh

The service path

A peer call is more than fetch().

OpenMesh turns a changing set of service instances into a routable peer pool with stable selection, deadlines, safe retries, circuit state and transport telemetry.

selection Rendezvous hashing

Stable ownership for keyed traffic with minimal movement when peers change.

retry Safety first

Unsafe methods are not retried implicitly. Deadlines cover the complete attempt chain.

circuit Per-peer state

Failures isolate bad instances without poisoning healthy peers or caller cancellation.

telemetry Transport-local signals

Attempts, successes, inflight, latency EWMA and last success/failure timestamps.

03 control plane

The state path

Topology and config move as versioned state.

Registration uses expiring leases. Discovery snapshots carry monotonic revisions. Configuration is immutable, compare-and-swap, and delivered over resumable SSE watches.

04 source model

One source of truth

TypeScript is the implementation.

The runtime is authored once under strict TypeScript and compiled into both module formats plus declarations. There is no parallel JavaScript implementation and no hand-maintained type mirror.

05 start here

Small core

Use one layer. Or the whole runtime.

server.ts 
import openmesh from 'openmesh-node';
import { jsonBody } from 'openmesh-node/plugins';

const app = openmesh();
app.use(jsonBody());

app.get('/users/:id', ctx => ({
  id: ctx.params.id
}));

await app.listen({ port: 3000 });
